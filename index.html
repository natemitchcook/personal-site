What I'm Building

Travel Card Guide

Personal Build / React • 2026

A guide to travel credit cards that compares welcome offers and annual benefits, includes a personal credit-use calculator, and explains how to find award flights with Seats.aero. Built in React 19 and TypeScript with Radix and shadcn components and Tailwind, compiled by Vite into a static page. All card data lives in one JSON file, so updating an offer is a data change, not a code change. GitHub Actions deploys it to S3 and CloudFront using short-lived OIDC credentials instead of stored AWS keys.

React TypeScript Vite S3 + CloudFront

Ruffi

Personal Build / Agentic App • 2026

An award-travel engine that finds flights bookable with points, ranks them against your actual points wallet, and alerts you when a meaningfully better option appears. One TypeScript service is the source of truth, exposed as both an HTTP API with an OpenAPI spec and an MCP server, so other agents use the same tools as the web app. Requests in plain English are parsed by deterministic code first and refined by a local Ollama model, and every model output is validated in code before it touches dates, seats, cabins, or points math. Availability comes from Seats.aero, with optional preference-aware ranking from TypeSafe Jev. Runs locally today; hosting is next.

Next.js TypeScript MCP Server Local LLM

Welvia

Venture / Agentic Commerce • 2026

Helps small businesses become usable by their customers' AI agents, not just findable. Instead of another SEO play, Welvia gives agents a clear action contract, an OpenAPI spec plus llms.txt, to read approved business facts, answer questions, and submit a complete, customer-approved request (like a catering order) that staff then confirm. Built on AWS with Lambda, API Gateway, DynamoDB, and CloudFront, with invitation-scoped access, duplicate-safe receipts, and an evaluation service that scores how well agents complete real tasks. How I Work

Listen first. I spend the first weeks doing intake, not building. The hardest question in AI right now isn't how to build something, it's choosing what to build. I find the problem with the widest blast radius and the clearest user pain.

Ship fast, measure everything. I prototype rapidly and let real usage data drive decisions. At Audible, that meant A/B testing at scale across 6 marketplaces. On the AI team, that means dogfooding every tool before anyone else sees it.

Make adoption the product. The best tools sell themselves. I design for zero friction: natural language interfaces, self-service, no training required. If people don't use it voluntarily, the product isn't good enough.
